name: 한국어 음성 인식 계약 검증
description: 실제 wire 설정과 음향 정확성을 구분해야 하는 이유 및 단계적 적용 원칙
---

언어를 강제한다고 설명하기 전에 실제 설치 SDK의 직렬화 후 요청과 제공자 지원 계약을 검증한다. mock connect 인자에 언어 코드가 들어 있다는 사실만으로 지원된다고 판단하지 않는다.

**Why:** Google GenAI 1.15.0은 AudioTranscriptionConfig의 languageCode를 빈 객체로 직렬화했다. 같은 SDK는 내부 END_OF_TURN event도 전송하지 않았고 audioStreamEnd만 지원했다. 설정과 진단이 실제 전송과 달랐다.

**How to apply:** SDK나 모델을 바꿀 때 소켓 직전 경계 테스트를 유지하고 현재 공식 문서와 대조한다. 대화 생성의 한국어 지시는 전사 언어 강제와 구분한다.

독립 STT 도입을 인식 정확성 개선과 동일시하지 않는다. 같은 실제 파형의 비교 결과와 남은 한계를 먼저 확인한다.

**Why:** 실제 API 합성 음성 비교에서 Live가 정확히 전사한 짧은 한국어를 mini STT는 외국어로 기록한 경우가 있었다. 재생성한 합성 음성에서는 재현되지 않아 모델 일반 성능 또는 실제 기기에서의 해결을 주장할 근거가 없었다.

**How to apply:** 확인 전 결과는 평가에 넣지 않고 실패 시 Live 원문으로 조용히 되돌리지 않는다. synthetic/모의 이벤트/실제 기기 시험 결과를 별도로 표시한다. 숫자 표기나 정상 혼합 언어의 문자 오류율을 사용자 감점 규칙으로 사용하지 않는다.

음성 턴 ID만으로 인식 검증 정책을 적용하지 않는다. run의 검증 요구와 해당 발화의 evidence를 확인하며, capture 수준의 필수 확인은 provider completion과 별도로 유지한다.

**Why:** 다른 언어·과거 음성도 같은 턴 ID 형식을 사용한다. 또한 분할 전사 이후 Live 완료가 도착하면 문구 일치만으로 필수 확인을 해제할 수 있다.

**How to apply:** 비한국어·legacy 호환성과 STT→provider 완료의 역순 이벤트를 함께 테스트한다. 원음 실패·분할 등의 보류 사유는 사용자의 명시적 확인으로만 해제한다.
