---
name: Tavus Full Pipeline boundaries
description: 사용자가 지정한 독립 Tavus 모드와 공통 PAL 재사용 원칙
---

Tavus 라이브 아바타는 Gemini Live 음성을 중계하는 모드가 아니라 Tavus가 STT·LLM·TTS·Avatar·Lip Sync를 모두 처리하는 독립 모드로 유지한다. 기존 텍스트와 Gemini Live 모드는 보존한다.

**Why:** 사용자가 Tavus Full Pipeline을 별도 모드로 구현하도록 명시적으로 요청했다.

**How to apply:** Tavus 경로에서 Gemini Live WebSocket이나 AvatarRouter 오디오 중계를 추가하지 않는다. 기존 평가 로직은 유지하고 제공자가 확정한 전사 기록을 어댑터로 연결한다.

Tavus를 직접 연결하지 말고 이미 연결된 아바타 라우터를 통해 연결해야 한다.

**Why:** 사용자가 직접 Tavus 연결 대신 기존 아바타 라우터를 사용하라고 명시적으로 정정했다.

**How to apply:** RoleplayX에서 Tavus API 키를 요청하거나 Tavus REST API를 직접 호출하지 않는다. 기존 라우터의 서버 전용 프로젝트 키 경계를 재사용한다. PCM 렌더러와 STT·LLM·TTS 전체 파이프라인을 혼동하지 않고, 라우터의 Full Pipeline 계약이 확인되지 않으면 우회 호출 대신 지원 필요 상태를 표시한다.

페르소나별 PAL 생성 대신 고정된 공통 PAL 하나를 재사용하고, 시작할 때 페르소나 특성과 시나리오를 동적 컨텍스트로 전달한다.

**Why:** 사용자가 최초에는 공통 PAL 하나만 사용하고 불필요한 기존 스키마 변경을 피하라고 요청했다. 이후 라우터의 세션별 PAL 생성·120초 제한·확정 대화록 API 부재를 설명하고 축소 연결과 기존 요구사항 유지 중 선택을 요청했을 때도 “기존 요구사항 유지”를 선택했다.

**How to apply:** 세션별 역할 변경을 위해 공유 PAL을 수정하지 않는다. 공통 PAL의 물리적 목소리 공유와 컨텍스트에 따른 말투·행동 차이를 구분하고, 실제 역할 유지나 미디어 품질은 모의 테스트로 검증됐다고 주장하지 않는다.

공통 PAL 재사용, 시나리오 목표 시간, 확정 대화록 평가 연결은 장기 요구사항이다. 단, 사용자는 이후 “현재 구현된 상태로 우선 라이브 아바타를 실행 할 수 있도록 구현해”라고 요청하여 현재 라우터 방식으로 우선 실행하도록 범위를 변경했다.

**Why:** 기존 요구사항 유지 선택 뒤 사용자가 현재 구현된 상태로 우선 실행할 수 있게 하라고 명시적으로 지시했다.

**How to apply:** 우선 실행 단계에서는 세션별 PAL·120초 제한·확정 대화록 및 평가 미지원 상태를 명시하고 연결한다. 공통 PAL 제약을 이유로 이 우선 실행을 다시 차단하지 않는다. 직접 Tavus 호출, 임시 자막의 확정 대화록 대체, 평가 연동 완료 주장은 금지한다.

라이브 대화의 유료 생성 여부·한도·준비 상태·원격 정리는 아바타 라우터가 판단한다.
앱은 사용자의 명시적 시작 요청을 자체 사전 점검이나 결과 불명 잠금으로 막지 않고,
수동 상태 확인·정리 재확인을 요구하지 않는다.

**Why:** 사용자가 “유료생성을 막지도 말고, 상태 확인도 필요없자나, 이건 아바타 라우터가 할일이야”라고 명시했다.

**How to apply:** 로그인·소유권·유효한 실행 컨텍스트와 같은 요청의 중복 클릭 방지는 유지한다.
한도 조회 결과로 유료 POST를 차단하거나, 이전 실패 뒤 상태 확인을 통과해야
수동 재요청할 수 있게 만들지 않는다. 시작·재시도는 명시적 사용자 동작일 때만
라우터로 전달하며 자동 유료 재시도는 하지 않는다. 예전 결과 불명 잠금 지침보다
이 사용자 지시를 우선한다.

Full Pipeline의 커스텀 아바타는 기존 PCM 렌더링 진단의 재생 검증 이력과
구분한다. 라우터의 `ready` 자산이 `liveValidation.status=unvalidated`일 수
있으며, 이를 Full Pipeline 시작 불가로 해석하지 않는다.

**Why:** 페르소나 수정 화면에서는 동작하던 동일한 자산이 시나리오에서는
재생 검증 이력 조건 때문에 라우터 세션 생성 요청 전에 거부된 사례가 있었다.

**How to apply:** 선택된 실행 스냅샷·프로젝트·자산·제공자 참조의 일치는
검증하되, Full Pipeline 생성은 진단용 검증·시드 활성화 조건으로 막지 않는다.
Full Pipeline 자체의 재요청을 다른 PCM 대화가 끼어드는 경우와 혼동하지 않는다.

라이브 아바타 화면은 현재 음성 라이브 화면과 동일하게 구성한다. 이전 이미지·텍스트 카드형 대화창을 기준으로 삼지 않는다. 기존 이미지·텍스트 대화는 없애지 않고 선택적으로 유지하며, 라이브 기록과 결과 피드백도 기존 저장·평가 구조로 연결한다.

**Why:** 사용자가 기존 화면을 구버전이라고 정정하며 “지금 음성 라이브 화면과 동일하게 구성”하라고 요청했다. 평가 기록 출처는 이전에 “라우터 확정 기록 사용”을 명시적으로 선택했다.

**How to apply:** 사용자가 지연되더라도 브라우저에서 전사를 표시하도록 요청했으므로, 미확정 대화 내역 표시는 라우터 확정 기록 기능 유무로 막지 않는다. 브라우저 자막이나 중단 전에 생성된 전체 AI 답변을 확정 평가 증거로 대체하지 않는다. AvatarRouter의 제공자 인증 최종 대화록 기능이 실제로 광고될 때만 확정 기록 저장·평가를 활성화한다. 라우터 수정 PR 준비, 운영 병합·배포, 유료 대화 검증은 서로 다른 단계로 보고한다.

피드백을 요청하는 라이브 아바타 종료는 음성 라이브와 같은 피드백 생성·진행·결과 화면으로 자동 연결한다. 확정 대화록 가져오기 완료와 리포트 생성 완료를 구분한다.

**Why:** 사용자가 “라이브 아바타 대화 종료후 음성 라이브와 동일하게 대화 내용을 기반으로 피드백 리포트를 생성”하도록 요청했다.

**How to apply:** 확정 기록 저장과 지속 평가 작업 등록을 확인한 뒤 공통 피드백 화면으로 이동한다. 임시 자막만 있거나 학습자 발화가 없는 경우 이 경로를 우회하지 않는다. 기간 연장 방안 정리는 운영 한도 변경·외부 유료 테스트 승인과 구분한다.

우측 상단의 라이브 아바타 대화 종료는 해당 시나리오의 상세 보기 창으로
돌아가는 동작이다. 이 명시적 나가기를 피드백 화면 자동 이동으로 대체하지 않는다.

**Why:** 사용자가 우측 상단 종료가 작동하지 않는다고 지적하고, 종료하면
시나리오 상세 보기 창으로 이동하도록 요청했다.

**How to apply:** 로컬 미디어와 화면 잠금을 해제하고 서버 종료 요청을 전달하되,
원격 정리나 대화록 제공이 지연돼도 나가기를 막지 않는다. 원격 정리 완료를
확인한 것처럼 표시하거나 기존 중복 생성 방지 상태를 지우지 않는다.

Daily 서버는 폐기된 브라우저 SDK의 실제 연결을 거부할 수 있으므로 모의 테스트·빌드 통과만으로 라이브 연결 호환성을 주장하지 않는다.

**Why:** 실제 브라우저 로그에서 SDK 지원 종료에 따른 연결 거부가 발견됐다. 화면이나 전사 로직만 수정하면 같은 연결 장애가 남는다.

**How to apply:** Daily 연결 실패 시 브라우저 로그의 SDK 지원 종료 메시지도 확인하고, 업데이트할 때 패키지가 요구하는 Node 버전과 함께 검증한다. 유료 통화 검증 여부는 별도로 명시한다.

Full Pipeline의 세션 시간은 라우터의 현재 한도를 따른다. 과거 렌더링 진단의 120초 제한을 공통 실행 계약에 적용하지 않는다.

**Why:** 라우터가 600초를 정상 응답했는데 앱의 120초 상한 검증이 이를 읽기 오류로 처리하여 유료 생성 전에 대화 시작을 막은 사례가 있다.

**How to apply:** 실행 시간은 라우터가 반환한 세션 만료 시각을 사용한다.
라이브 대화 시작 전 한도 응답을 필수 게이트로 다시 도입하지 않는다.
한도를 읽지 못한 경우 임의의 과거 값으로 대신하지 않는다.

이 원칙은 페르소나 수정 화면의 관리자 연결 테스트에도 적용한다.
앱은 유·무료 세션 관리, 비용·잔여 시간에 따른 연결 차단, 수동 영상·음성
재생 인증과 보고를 하지 않는다. 아바타 라우터 연결과 응답 표시만 담당한다.

**Why:** 사용자가 “유무료 관여하지 말고, 무조건 제대로 연결시켜 여기서
유료무료 관리할 필요 없어 연결이나 제대로 해, 유무료 관리는 아바타 라우터가
할꺼야”라고 반복해서 명시했다. 검증도 여기서 할 필요가 없다고 지시했다.

**How to apply:** 로그인·소유권·선택 자산의 참조 일치와 진행 중 동일 요청의
중복 클릭 방지는 유지한다. 과거 실패에 라우터 세션 ID가 없다면 기존 세션
종료·정리 요구로 해석하지 않는다. 라우터가 자체 검증 선행 조건으로 거절하면
앱에서 재생 증거를 꾸미거나 다른 실행 용도로 위장하지 말고 실제 거절 원인을
표시한다. 라우터 정책 변경과 이 앱의 차단 제거를 구분해서 보고한다.

페르소나 테스트 성공과 라우터 재게시만으로 일반 대화 경로의 수정 반영을
판정하지 않는다. 배포한 소스와 실제 연결 서버의 소스 지문을 함께 확인한다.

**Why:** 사용자가 라우터를 다시 배포하고 페르소나 테스트도 성공했다고
확인했지만 실제 연결 서버는 여전히 수정 전 소스 지문을 반환했다.

**How to apply:** 재게시하지 않았다고 단정하지 않는다. 검증 목적 요청과
일반 대화 요청의 정책 차이를 비교하고, 병합된 GitHub 소스·게시 대상
프로젝트의 소스·실제 응답 서버를 구분한다. 일반 대화를 검증 목적으로
위장하거나 재생 증거를 만들어 우회하지 않는다.
