---
name: iOS realtime audio routing
description: WebKit 실시간 음성 세션에서 Bluetooth 입출력 경로를 안정적으로 유지하는 규칙
---

iOS의 실시간 양방향 음성 대화는 `AudioContext` 또는 `getUserMedia`를 만들기 전에 Audio Session을 `play-and-record`로 설정하고, 대화가 끝날 때까지 유지한다. 종료 후에만 `auto`로 복원한다. `setSinkId`가 없는 iOS에서는 앱 출력 장치 ID를 저장하거나 강제하지 않고 현재 iOS 시스템 경로를 사용한다.

**Why:** WebKit이 재생 컨텍스트를 먼저 만들면 본체 스피커 경로에 묶일 수 있고, 통화 중 프로필 변경은 Bluetooth 헤드셋의 마이크·스피커 경로를 분리할 수 있다. 늦게 도착한 이전 연결 이벤트가 새 통화의 세션을 해제하는 경합도 방지해야 한다.

**How to apply:** 연결, 마이크 획득, 백그라운드 복귀 전에 통화 프로필을 재확인하고, 종단 연결 해제에서만 해제한다. 비동기 연결 콜백은 현재 연결 소유권을 검사한다. iOS가 개별 입력을 노출하지 않으면 빈 장치 ID로 시스템 기본 입력을 사용한다.

iOS의 최초 음성 연결은 사용자가 음성 시작 또는 전환을 누를 때 마이크를 준비한다. 영상 인트로 중 자동 연결보다 사용자 동작에 따른 권한 요청을 우선한다. 자동 네트워크 재연결은 권한 거부를 반복 요청하지 않는다.

**Why:** Safari의 Permissions API 조회 지원 여부나 로컬 저장값으로 권한을 확정할 수 없고, 페이지 방문이나 인트로 재생만으로 마이크 승인 요청을 띄우지 않아야 한다.

**How to apply:** 실제 마이크 획득 결과를 권한 판단의 근거로 삼는다. 기기 목록에 라벨이 숨겨져 있어도 성공한 획득 결과를 부정하지 않는다. 권한 확인용 스트림과 실제 녹음 스트림은 소유권을 분리한다.

사용자는 아이폰 주요 사용성 개선이 완료되어 적용된 상태라고 확인했다. 서버 중심 대화 기록 재설계에서는 적용된 아이폰 개선을 유지하며 동일 작업을 다시 구현하지 않는다.

**Why:** 사용자가 완료·적용 상태를 명시하고, 최근 완료 내용과 비교하여 미진행된 서버 재설계만 시작하라고 요청했다.

**How to apply:** 대기열의 아이폰 관련 상태만 보고 중복 구현하지 않는다. 새 기록 계약과의 연결에 필요한 회귀 검증은 기존 개선을 보존하면서 수행한다.
