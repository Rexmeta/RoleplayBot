---
name: 동시 음성 장애 증거
description: 교육 행사 장애의 증거 범위와 모의 부하 결과 해석 원칙
---

행사 장애는 연결 수명주기, provider 오류, 음성 입출력/OS 경로를 별도 계층으로 분석한다. 행사 시각·시간대·revision·전체 로그·quota가 없으면 근본 원인을 미확인으로 남긴다. 저장소 Cloud Run 정의가 있어도 실제 배포 환경으로 간주하지 않는다.

**Why:** 실제 배포 조회는 Replit Autoscale을 가리키는 반면 저장소에는 Cloud Run timeout 정의가 있었고, 최근 로그에는 자원 소진과 음성 억제 경고가 함께 있었다. 이들만 합쳐 한 원인으로 단정하면 잘못된 완화책을 선택하게 된다.

**How to apply:** 모의 부하는 앱 코드 재현에만 사용하며 provider 수용량·안전 동시 인원으로 발표하지 않는다. 합성 PCM/오프라인 WebAudio는 디지털 출력만 검증하며 실기기 청취 없이 OS route나 체감 음량을 검증했다고 쓰지 않는다. 운영 변경과 유료 실 API 부하는 별도 승인 대상으로 분리한다.

출력 끊김 조사에서는 필터된 로그 두 줄을 연속 오디오 청크로 간주하지 않는다. 로컬 턴 번호 증가도 새 provider 응답이 시작됐다는 증거로 사용하지 않는다.

**Why:** 더 좁은 UTC 구간을 재조회하니 긴 공백처럼 보였던 두 로그 사이에 여러 청크가 있었다. 취소 ACK의 로컬 턴 변경과 실제 provider 경계는 독립적이어서 잔여 오디오도 새 번호를 받을 수 있다.

**How to apply:** 해당 구간의 모든 오디오 후보와 연결 식별을 먼저 대조한다. 브라우저 예약·종료와 provider 경계가 없으면 실제 무음 길이 및 옛 음성 재개는 미확인으로 남긴다.
