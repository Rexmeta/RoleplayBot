이 로그를 보면 이전보다 훨씬 중요한 단서를 찾을 수 있습니다.

## 가장 눈에 띄는 부분

```
🖼️ 시드 이미지 로드:
neutral.webp
(image/webp)
```

즉, 지금 시드 이미지는 **WEBP**입니다.

그런데 앞에서 보여준 예시는

```json
{
  "mimeType": "image/jpeg"
}
```

였습니다.

실제 로그에서는

```
image/webp
```

를 보내고 있습니다.

---

# 제가 가장 먼저 해볼 것은 WEBP 제거입니다.

Veo 3.1은 공식적으로 이미지 입력을 지원하지만, **WEBP는 JPEG나 PNG보다 안정성이 떨어진 사례가 꽤 있습니다.**

특히 사람 얼굴 + WEBP는

```
raiMediaFilteredCount=1
```

이 발생하는 사례가 종종 있습니다.

먼저

```
neutral.webp
```

↓

```
neutral.jpg
```

또는

```
neutral.png
```

로 바꿔보세요.

이것만으로 해결되는 경우가 있습니다.

---

# 두 번째

이 프롬프트는 아직도 너무 제약이 많습니다.

예를 들어

```
Only motion allowed

Lips sealed shut

No head movement whatsoever

No nodding

No tilting

No body sway

No gestures

No shoulder movement

Perfect loop

First and last frames identical
```

거의 10개의 금지 규칙입니다.

Veo는 이런 프롬프트를 별로 좋아하지 않습니다.

오히려

```
A Korean office worker seated at a desk.

Looking naturally at the camera.

Calm neutral expression.

Natural blinking.

Subtle breathing.

Maintain a relaxed upright posture.

Static camera.

Soft office lighting.

6-second seamless loop.
```

정도가 훨씬 안정적입니다.

---

# 세 번째

이 로그가 중요합니다.

```
raiMediaFilteredCount=1
```

Google 내부에서는

```
RAI
```

가

```
Responsible AI Filter
```

입니다.

즉

**생성 자체가 시작도 못했습니다.**

영상 생성 중간에 실패한 것이 아니라

```
입력 단계에서 차단
```

됐습니다.

---

# 그런데...

로그를 보면

```
hasSeedImage=true
```

입니다.

이게 상당히 중요한 힌트입니다.

즉

```
Seed Image
↓

RAI
↓

Reject
```

입니다.

Prompt가 아니라

입력 이미지까지 포함한 전체 요청을 필터가 거부한 것입니다.

# 제가 의심하는 순위

### 1위 (★★★★★)

WEBP

가장 먼저 JPEG로 바꾸세요.

---

### 2위 (★★★★★)

실사 얼굴

*

정면

*

Seed Image

*

Veo3.1

조합 자체가 필터에 걸리는 경우

---

### 3위 (★★★★☆)

Prompt가 너무 강한 제약

---

### 4위 (★★★☆☆)

시드 이미지 자체

예를 들어

* 너무 사실적
* AI 얼굴
* 피부 보정
* 미성년자로 보일 가능성

# 하나 더 궁금한 점

로그에서

```
🖼️ 시드 이미지 로드:
neutral.webp
(image/webp)
61596 bytes
```

이 이미지는

* **실제 사람 사진인가요?**
* **Flux / GPT Image / Midjourney 같은 AI 생성 이미지인가요?**
* **직접 촬영한 사진인가요?**

그리고 해상도는

* 1024×1024
* 768×768
* 1536×1536
* 다른 크기

중 무엇인가요?

이 두 정보만 알면, 현재 문제가 **이미지 자체 때문인지**, **포맷 때문인지**를 더 정확하게 좁힐 수 있습니다.
