이건 파일 형식(PNG/JPEG)보다 **Veo의 Image-to-Video 특성과 RAI 정책**에 가까운 문제입니다.

결론부터 말씀드리면,

* **PNG로 바꾼다고 해결될 가능성은 낮습니다.**
* **"한국인"을 프롬프트만으로 강하게 지정하는 것도 기대만큼 안정적이지 않습니다.**
* **가장 중요한 것은 시드 이미지의 생성 방식과 구성입니다.**

---

# 왜 시드 이미지를 넣어도 다른 사람이 되는가?

Veo의 시드 이미지는 **"첫 프레임(reference)"**이지 **"이 사람을 반드시 유지하라"**는 강제 조건이 아닙니다.

즉,

```
시드 이미지
+
프롬프트
```

를 합쳐서 새 영상을 생성합니다.

만약 시드 이미지의 신호가 약하거나 프롬프트가 일반적이면 모델이 새로운 사람을 만들어 버릴 수 있습니다.

---

# "한국인"이 잘 안 먹는 이유

예를 들어

```
A Korean man
```

이라고 쓰더라도

모델은

```
동아시아 남성
```

정도로만 해석하는 경우가 많습니다.

또한 공정성(fairness) 정책 때문에 특정 민족적 특징을 과도하게 강조하지 않는 방향으로 동작할 수 있습니다.

그래서 "한국인"만으로는 원하는 얼굴 특성이 안정적으로 유지되지 않는 경우가 있습니다.

---

# PNG가 더 좋을까?

제 경험과 공개 사례를 종합하면

* JPEG
* PNG

둘 다 지원됩니다.

품질 측면에서는

* PNG는 무손실
* JPEG는 손실 압축

이 차이는 있지만,

**RAI 필터 통과율이 PNG라서 높아진다는 근거는 없습니다.**

오히려

* 1024×1024
* 적절한 얼굴 크기
* 깨끗한 조명

이 더 중요합니다.

---

# Gemini Image → Veo가 항상 잘 이어지는 것도 아닙니다

많은 분들이

```
Gemini Image
↓

Veo
```

를 사용하지만

이미지가

* 너무 사실적
* 여권사진 스타일
* 얼굴만 크게
* 완전 정면

이면 오히려 RAI가 민감하게 반응하는 경우가 있습니다.

---

# RoleplayBot이라면 추천하는 시드 이미지 규격

현재는

```
얼굴 중심
```

처럼 보이는데,

오히려

```
회의실

+

책상

+

노트북

+

허리 위

+

약간의 여백
```

구성이 더 안정적입니다.

예를 들어

```
35~45%

인물

55~65%

배경
```

정도가 좋습니다.

얼굴이 화면을 꽉 채우는 것보다 안정적입니다.

---

# 프롬프트도 "정체성"과 "동작"을 분리하세요

현재는

```
한국인

회의실

정면

무표정

깜빡임
```

을 한 프롬프트에 다 넣고 있습니다.

추천하는 구조는

### Identity

```
A Korean male office worker in his 30s.

Business casual attire.

Modern office meeting room.

Upper body visible.

Maintain the same appearance as the reference image.
```

---

### Motion

```
Natural blinking.

Subtle breathing.

Calm attentive posture.

Looking at the camera.
```

---

### Camera

```
Static camera.

Soft office lighting.

6-second seamless loop.
```

이렇게 분리하면 상태별 프롬프트도 재사용하기 쉽습니다.

---

# 시드 이미지를 만드는 프롬프트도 중요합니다

Gemini Image로 만들 때부터

```
A realistic Korean office worker seated naturally at a meeting table.

Upper body visible.

Modern office meeting room.

Business casual clothing.

Soft daylight.

Camera at eye level.

Natural facial expression.

No dramatic lighting.

No shallow depth of field.

Medium shot.
```

처럼 **영상의 첫 프레임**을 만든다는 생각으로 생성하는 것이 좋습니다.

여권사진처럼 얼굴만 크게 생성하는 것보다 성공률이 높습니다.

---

# 제가 제안하는 구조 (RoleplayBot에 가장 적합)

RoleplayBot이라면 **이미지 생성과 영상 생성을 분리해서 설계**하는 것이 좋습니다.

1. **이미지 생성 단계**

   * Persona Sheet 생성
   * 동일 인물의 "중립 포즈"를 표준 규격으로 생성
   * 상반신, 책상 포함, 회의실 배경

2. **영상 생성 단계**

   * 시드 이미지는 절대 수정하지 않음
   * 상태(State)별로 동작만 변경 (`idle`, `listening`, `thinking`, `speaking`)

3. **검증 단계**

   * RAI에서 차단되면 자동으로 시드 이미지를 재생성
   * 얼굴 클로즈업 대신 여백이 있는 구도로 재시도
   * 조명·구도만 바꾼 2~3개의 대체 시드를 준비

이렇게 하면 단순히 PNG/JPEG를 바꾸는 것보다 성공률을 높일 가능성이 큽니다.

---

## 제가 추가로 추천하는 전략

RoleplayBot은 결국 **같은 인물을 수십 개의 상태 영상으로 확장**하는 시스템입니다. 이 경우에는 **"Veo에 넣기 좋은 시드 이미지 생성기"**를 별도로 만드는 것이 효과적입니다.

예를 들어 Gemini Image 생성 시부터 다음 규칙을 강제합니다.

* 허리 위 또는 가슴 위 구도
* 얼굴이 프레임 높이의 약 30~40%만 차지
* 정면이지만 약간의 자연스러운 자세
* 회의실 배경이 충분히 보임
* 균일한 실내 조명
* 단색 의상, 단순한 배경
* 과도한 사실감이나 뷰티 보정 제거

이런 표준 시드를 사용하면 Veo에서의 일관성과 통과율이 개선될 가능성이 있습니다. 다만 RAI는 서버 측 정책이므로, 동일한 이미지라도 시점이나 모델 버전에 따라 결과가 달라질 수 있다는 점은 감안해야 합니다.
