## 1. 가장 중요한 문제: Simulation을 "core domain"이라고 하면서 9개라고 표현

현재 문서에는:

> "nine core domains ... Simulation"

이라고 되어 있습니다. 

그리고 Step 1에서는:

> "nine core domains plus the Simulation domain"

이라고 했습니다. 

즉 논리적으로는:

**원래 9개 → Simulation 추가 → 10개**

가 맞습니다.

하지만 `API Boundary`는 domain이 아니므로 최종적으로는:

### Core domains = 10개

```text
Persona
Scenario
Session
Evaluation
Emotion
Voice
Avatar
Auth
Simulation
+ Interaction/Trace?  ← 아직 domain은 아님
```

그리고:

```text
API Boundary = cross-cutting boundary
```

입니다.

따라서 "nine core domains"라는 표현은 제거하는 것이 좋습니다.

### 추천

```text
the ten core domains (Persona, Scenario, Session, Evaluation,
Emotion, Voice, Avatar, Auth, Simulation, and ...)
```

그런데 여기서 Interaction/Trace는 **현재 domain으로 승격하지 않기로 했기 때문에** 결국:

> **nine original domains + Simulation = ten core domains**

라고 명확하게 쓰는 게 가장 좋습니다.

# 11. 딱 하나 더 추가한다면 "Evidence"입니다

제가 마지막으로 추가하고 싶은 것은 이것 하나입니다.

현재 문서는:

> Risk
> Actual
> Expected
> Files

를 기록합니다.

그런데 나중에 우리가 이 문서를 보고 리팩토링할 때:

> "왜 이것을 Critical이라고 판단했지?"

가 될 수 있습니다.

따라서 중요한 dependency / hotspot에:

```text
Evidence
```

를 넣으세요.

예:

| From       | To           | Actual | Expected | Risk     | Evidence                  |
| ---------- | ------------ | ------ | -------- | -------- | ------------------------- |
| Evaluation | Conversation | direct | Trace    | High     | `evaluationEngine.ts:123` |
| Service    | Gemini SDK   | direct | Provider | Critical | `foo.ts:87`               |

단, **모든 dependency에 line number를 요구하면 작업량이 너무 커집니다.**

따라서:

> Critical / High risk 항목만 concrete file + symbol/line evidence를 남긴다.

정도로 제한하는 게 좋습니다.

### Step 9에 한 문장 추가

```text
For Critical and High risks, record concrete evidence
(file path and symbol or line reference) sufficient to verify the finding.
```

이 정도면 됩니다.
