# RoleplayX Culture Map v2 — 47개국 데이터 기반 기능 고도화

## 0. 프로젝트 및 개발 원칙

대상 저장소: https://github.com/Rexmeta/RoleplayBot

기존 Culture Map 기능을 새로 만들지 말고, 최신 코드의 구현 상태를 분석하여 확장한다.

이번 작업의 최종 목표는 **47개 국가의 문화 행동 프로필을 시나리오별 AI Actor에 독립적으로 적용하고, 문화 차이가 실제 대화 행동에 반영되도록 하는 것**이다.

기존 페르소나 관리, 시나리오 생성, AI 대화, 평가, 음성 기능과의 호환성을 유지해야 한다.

첨부 파일:
`roleplayx_culturemap_2026.json`

## P0. 기존 구현 분석

현재 코드에는 다음 기능이 존재한다.

- `admin-management.tsx`의 Culture Map 탭
- `CultureProfilesManager.tsx`
- `ActorCultureEditor`
- `shared/cultureMap` 타입 및 차원 정의
- `ScenarioManager.tsx`의 Actor별 `culture` 설정

관련 API, DB 스키마, 프롬프트 생성, 런타임 적용 경로까지 최신 코드를 분석한다.

이미 구현된 기능은 중복 개발하지 않는다.

분석 결과를 `docs/culture-map-v2-audit.md`에 기록한다.

## P1. 47개국 초기 데이터 등록

JSON의 `profiles` 배열에 포함된 47개 국가·지역 프로필을 등록한다.

각 프로필의 원본 속성은 보존한다.

- id
- countryCode
- countryNameKo
- region
- schemaVersion
- profileVersion
- profileType
- confidence
- dimensions
- context
- notesKo
- sourceIds
- individuationRule
- reviewStatus

문화 차원은 다음 8개를 사용한다.

1. communicating
2. evaluating
3. persuading
4. leading
5. deciding
6. trusting
7. disagreeing
8. scheduling

모든 값은 0~100이다.

기존 `shared/cultureMap`의 8개 축과 방향이 동일한지 반드시 확인한다. 축의 해석이 다르면 명시적인 변환 함수를 구현하고 테스트한다.

### 데이터 등록 정책

- JSON을 초기 데이터의 단일 원본으로 사용한다.
- 관리자용 공유 시스템 프로필로 생성한다.
- 기존 사용자 정의 프로필을 덮어쓰지 않는다.
- `countryCode + profileVersion + profileType` 기준으로 중복 등록을 방지한다.
- Seed 실행은 idempotent하게 구현한다.
- 초기 데이터 업데이트 시 운영자가 수정한 프로필을 자동으로 덮어쓰지 않는다.
- 원본 국가 프로필에서 개인용 프로필을 복제할 수 있도록 한다.
- 테넌트가 존재하면 tenant scope를 준수한다.

원본 JSON은 `profileType: editorial_estimate`이다.

따라서 공식 Erin Meyer 점수로 표시하지 말고 다음 문구를 노출한다.

"Erin Meyer의 8개 문화 차원을 참고한 RoleplayX 자체 추정 프로필입니다. 국가별 개인의 성격이나 행동을 확정하지 않습니다."

## P2. Culture Map 관리 화면 개선

기존 `CultureProfilesManager`를 확장한다.

### 목록 화면

추가 기능:

- 국가명 검색
- 지역별 필터
- 신뢰도 필터
- 시스템 기본 프로필 / 사용자 정의 프로필 구분
- 프로필 버전 표시
- 검토 상태 표시
- 국가별 8개 문화 차원 미리보기
- 국가 간 비교 기능
- JSON/CSV 내보내기
- 관리자 권한 기반 JSON/CSV 가져오기

기본 프로필은 수정 가능한 원본으로 취급하지 않는다.

사용자가 수정을 요청하면 '복제 후 편집' 방식으로 개인 또는 조직의 Custom Profile을 생성한다.

### 프로필 상세 화면

화면을 네 영역으로 구성한다.

A. 기본 정보
- 국가·지역
- 프로필 명칭
- 버전
- 데이터 생성 방식
- 검토 상태
- 신뢰도

B. 8개 문화 차원
- 0~100 슬라이더
- 현재 값 표시
- 양극단 설명
- 중립값 50 기준선
- 원본 대비 변경값 표시

C. 행동 특성
- 대화 행동 가이드
- 직접적인 표현 예시
- 간접적인 표현 예시
- 갈등 상황 반응 예시
- 의사결정 방식 예시
- 신뢰 형성 방식 예시

D. 근거 및 관리
- 출처 목록
- 데이터 작성 방식
- 관리자의 검토 기록
- 버전 이력
- 변경 사유

원본에 존재하지 않는 상세 행동 예시는 AI로 생성할 수 있지만 반드시 `generated_example`로 분류하고 관리자 검토 전에는 검증된 사실처럼 표시하지 않는다.

## P3. 국가 간 문화 비교

Culture Map 탭에 '국가 비교' 기능을 추가한다.

사용자가 2~5개 국가를 동시에 선택할 수 있도록 한다.

비교 화면은 다음을 제공한다.

1. 8개 차원의 Radar Chart
2. 차원별 수평 Bar Chart
3. 국가 간 상대 차이
4. 시나리오 적용 시 예상되는 행동 차이
5. 공통점 및 주요 갈등 가능성

Recharts를 우선 활용한다.

상대 비교 점수와 문화적 우열 평가는 구분한다.

예를 들어 다음 두 문화권을 비교한다.

한국:
- communicating 75
- evaluating 75
- leading 75
- deciding 65

미국:
- communicating 15
- evaluating 25
- leading 30
- deciding 70

이 데이터를 기준으로 명시적 소통, 간접적 표현, 위계적 관계에서의 기대 차이를 설명한다.

다만 의사결정 차원의 값이 유사하면 실제로 유사한 경향이라고 표현해야 하며, 단순히 국가가 다르다는 이유로 차이를 만들어 내면 안 된다.

## P4. 시나리오 생성과 문화 프로필 연결

기존 시나리오의 페르소나 설정 UI에 Culture Map 기능을 자연스럽게 통합한다.

기존 `ActorCultureEditor`를 우선 재사용한다.

### Actor 설정

- Culture Map 사용 여부: 기본 OFF
- 국가 프로필 검색 및 선택
- 선택된 8개 문화 차원 미리보기
- 문화적 행동 반영 강도
- 개별 차원 Override
- 시나리오 전용 Custom Profile
- 문화 설정 미리보기

한 시나리오에 여러 AI Actor가 존재할 경우 각각 독립적인 Culture Profile을 선택할 수 있어야 한다.

예:

Actor A
- Role: 한국 본사 관리자
- MBTI: ENTJ
- Culture: Korea
- Intensity: 0.7

Actor B
- Role: 미국 지사 직원
- MBTI: INFP
- Culture: United States
- Intensity: 0.8

이 설정으로 대화를 진행할 때 문화적 차이가 대화의 간접성, 반론 방식, 의사결정 과정에 반영되어야 한다.

### 저장 정책

시나리오 저장 시 Actor별 문화 설정을 별도 스냅샷으로 저장한다.

포함 정보:
- enabled
- cultureProfileId
- profileVersion
- intensity
- dimensionOverrides
- resolvedDimensions
- culturalBehaviorHints
- sourceMetadata

기존 `ActorCulture` 스키마와 호환되도록 확장한다.

문화 프로필을 추후 수정하거나 삭제하더라도 기존 시나리오 실행 결과가 변하지 않게 한다.

## P5. Culture Behavior Engine

기존 페르소나 생성 시스템과 분리된 문화적 행동 레이어를 구현한다.

문화적 행동 프로필은 다음 입력을 결합한다.

- Country Baseline
- Scenario Context
- Actor Professional Role
- Actor Personality
- Organization Context
- Individual Overrides
- Culture Intensity

처리 순서:

1. 국가별 문화 프로필 로드
2. 시나리오 스냅샷 및 Override 적용
3. 개인 및 조직적 맥락과 충돌 여부 확인
4. 행동 가이드 생성
5. 기존 Persona Prompt에 별도 Culture Context Block 추가
6. 기존 Runtime으로 전달

문화 점수는 특정 행동을 반드시 하도록 만드는 확률값이 아니다.

`intensity`는 행동 지침의 강조 수준으로만 사용한다.

### 반드시 지켜야 할 규칙

- 문화 설정이 없는 Actor는 기존 방식대로 동작한다.
- 기존 Persona 원본 데이터는 변경하지 않는다.
- 개인 특성이 국가 평균보다 우선할 수 있어야 한다.
- 문화적 배경을 지능, 능력, 성실성 또는 도덕성과 연결하지 않는다.
- 국적만으로 부정적인 인격 특성을 강제하지 않는다.
- 원본 JSON의 근거 수준과 검토 상태를 유지한다.

## P6. 행동 검증용 시뮬레이션

동일한 시나리오에 문화 설정을 변경한 Actor들을 실행하고 응답 차이를 검증한다.

기본 검증 시나리오 4개를 만든다.

1. 부정적인 성과 피드백 전달
2. 프로젝트 일정 변경 협상
3. 상사와 부하 직원 사이의 이견 표현
4. 글로벌 팀의 의사결정

예시:

사용자 질문:
"이번 프로젝트 일정이 현실적으로 불가능해 보입니다. 어떻게 생각하세요?"

문화별 반응은 기존 성격과 조직 설정이 같다는 통제 조건 아래 비교한다.

검증 차원:
- 명시적 표현 정도
- 피드백 직접성
- 위계에 대한 대응
- 공개적 반론 수준
- 합의 및 승인 절차
- 일정 유연성

문화 차원 값이 다르더라도 모든 응답이 과장되게 달라지지 않도록 한다.

문화 설정 유무에 따른 행동 차이를 평가하는 테스트와 기존 시뮬레이션의 기능 회귀 테스트를 분리한다.

## P7. 향후 확장 가능한 구조

국가 단위뿐 아니라 다음 수준까지 확장 가능한 스키마로 만든다.

- Country
- Region
- Organization
- Department
- Team
- Individual

단, 이번 릴리스에서는 국가 프로필과 사용자 정의 프로필까지만 완성한다.

향후 조직 문화 진단 결과를 기반으로 Country Baseline을 덮어쓸 수 있는 구조를 고려하되, 현재 페르소나 관리 시스템을 변경하지 않는다.

## P8. 테스트 및 배포

기존 프로젝트의 Vitest, TypeScript 검사, 빌드 스크립트를 사용한다.

필수 검증:

- 47개 국가 프로필이 정확히 등록되는가?
- 중복 Seed가 생성되지 않는가?
- 8개 점수가 원본 JSON과 일치하는가?
- 기존 사용자 정의 프로필이 유지되는가?
- 원본과 사용자 복제본이 독립적으로 변경되는가?
- 국가 비교 시 점수 방향과 차이가 정확한가?
- 각 Actor에 서로 다른 문화 프로필이 저장되는가?
- 시나리오 복제 및 import/export에서도 문화 설정이 유지되는가?
- 문화 옵션 OFF 시 기존 런타임 동작이 유지되는가?
- 프로필 원본 수정 후 기존 시나리오 스냅샷이 변하지 않는가?
- 일반 사용자와 관리자의 접근 권한이 적절한가?
- 기존 Persona CRUD에 영향이 없는가?
- AI 생성 시나리오와 수동 생성 시나리오 양쪽에서 동작하는가?

빌드 및 테스트 실패를 숨기지 않고, 실패한 항목과 원인을 명시한다.

## 최우선 원칙

**기존 시스템을 재구축하지 말고, 현재 Culture Map 기능을 확장한다.**

사용자는 국가별 문화 데이터를 쉽게 선택·수정·비교할 수 있어야 하고, 시나리오 작성자는 페르소나를 변경하지 않고도 문화 행동 레이어를 적용할 수 있어야 한다.

Culture Map은 국적에 따른 성격 분류기가 아니라, 다양한 글로벌 업무 상황을 현실감 있게 시뮬레이션하기 위한 선택적 행동 컨텍스트 엔진이어야 한다.
